# Architecture — zie-test-framework

**Last updated:** 2026-04-02

## Overview

Server-based AI Automated Testing Framework with local agent execution.

**Architecture Pattern:** Client-Server with outbound WebSocket

## Structure

```text
zie-test-framework/
├── server/          # Docker container (VPS) - WebSocket server, API, DB
├── agent/           # Local CLI - WebSocket client, test execution
├── tests/           # Test specs generated by LLM
└── evidence/        # Local artifacts (screenshots, logs)
```

## Component Relationships

```text
┌─────────────────┐
│   Notion        │ (Story input/output)
│   API           │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   Server        │ (Docker on VPS)
│  - WebSocket    │
│  - PostgreSQL   │
│  - Google OAuth │
│  - Notion Sync  │
└────────┬────────┘
         │ (outbound WebSocket)
         ▼
┌─────────────────┐
│   Agent         │ (Local execution)
│  - Playwright   │
│  - Chrome       │
│  - LLM Gen      │
└─────────────────┘
```

## Data Flow

1. User creates story in Notion
2. QA approves story in Web UI
3. Server sends story to Agent via WebSocket
4. Agent reads story → LLM generates test spec
5. Agent runs Playwright test locally
6. Agent uploads evidence to Google Drive
7. Agent syncs results to Notion + Server

## Key Constraints

- Agent uses **outbound WebSocket only** (no port forwarding)
- No GitHub storage - all local, evidence in Google Drive
- Multi-user support via Google OAuth
- Server-controlled architecture
